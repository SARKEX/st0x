<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser DOM → Sentry Replay → Sentry SaaS | Recorded text/inputs cross here; D-03 masking is the control |
| Sentry Replay worker → CSP `worker-src` | If CSP blocks, Replay silently degrades |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-2-C | Information disclosure | Sentry Replay capturing sensitive DOM (addresses, balances, error messages, signing UI) | mitigate | D-03 `maskAllText: true` + `maskAllInputs: true` + `blockAllMedia: true` (belt-and-braces). Replay shows user motion, not content. Test 3+4 in Task 1 are the regression guard. ASVS V8. |
| T-2-D | Information disclosure | Cookie-consent bypass for Sentry Replay (Sentry runs from module load; PostHog gated behind consent) | accept | Per RESEARCH Open Question 3, treat on-error Replay as "essential" (activates only when an error occurs; no proactive recording per D-02). Operator/legal stance documented in Plan 04 PRIVACY-REVIEW. No code change. |
| T-2-G | Tampering | CSP `worker-src 'self' blob:` regression — future CSP edit silently breaks Replay | mitigate | Task 1 CSP regression test asserts substring presence. ASVS V14. |
| T-2-H | Information disclosure | `trade_id` Sentry tag visible in Sentry UI to Sentry-account members | accept | `trade_id` is opaque UUIDv4 with no derivation from PII (RESEARCH §Security Domain). Cannot be reversed to identify a user. Same risk class as `request_id` already in Sentry events. |

</threat_model>
