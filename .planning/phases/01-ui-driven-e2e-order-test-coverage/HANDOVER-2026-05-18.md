## What changed this iteration (architectural baseline)

The previous handover (df92215) had marketBuy passing but with a stub layer that decayed: Hermes 503, ST0x outputVaultBalance mutation, vault prefunding — each was patching a symptom of LIVE-data-source-vs-fork-state divergence. By the time I picked up the branch, the stubs had grown to 5 layers and marketBuy was failing too.

I replaced the stub layers with three architectural pieces:

### 1. Dynamic `FORK_BLOCK` (`globalSetup.ts:63-96`)
Resolves to `latest - 60` blocks of the configured archive RPC at startup, validated to land inside NYSE market hours. Override via `FORK_BLOCK=<n>` env var. Picking a fork close to "now" minimizes drift between LIVE data sources (Goldsky subgraph, ST0x REST API, Pyth Hermes) and the fork's on-chain state.

### 2. Fork-aware ST0x orders stub (`forkOrdersStub.ts`)
Intercepts `/api/st0x/v1/orders/token/**`. Passes through the LIVE proxy for order discovery (orderHashes + tokens + orderBytes + metadata), then **re-quotes every pre-fork order against anvil** via a `RaindexClient` whose YAML points the RPC at `http://127.0.0.1:8545`. Substitutes the fork-derived `ioRatio` + `maxOutput` into the API response.

Key details:
- Filters to `timestampAdded < forkTimestamp` so the cache only attempts orders that exist on the fork
- Parallel `getQuotes` via `Promise.all` (~30-60s cache build vs ~2min serial)
- Cache is module-scoped → built once per worker, reused across all tests
- Vault balance still subgraph-cached (not fork-read); fine for near-now forks, would need an `eth_call` against the orderbook's `vaultBalance` for genuinely old forks

### 3. Goldsky GraphQL cache + 429 retry (`fixtures.ts:194-241`)
The Raindex SDK in the BROWSER hits Goldsky directly during the hydration step (`marketOrderExecution.ts:307-336` — one `getOrders` per walk-fill). Without intervention, the cumulative burst trips Goldsky's free tier (429 with no CORS headers, browser sees CORS error, SDK can't hydrate, preflight collapses with `preflight_chain_unreachable`).

The stub:
- Caches every successful (200) response by `method|URL|body` key
- Retries on 429 with exponential backoff (5s × attempt, up to 5 attempts)
- Injects `access-control-allow-origin: *` on cached playbacks
- Cache is module-scoped → shared across the workers=1 suite run

### Supporting changes
- Switched primary test token to **wtCOIN** per CLAUDE.md guidance (Pyth feed, no st0x off-chain oracle dependency)
- Limit-deploy spec dropped its hand-rolled `takeOrders3` calldata (the deployed orderbook is a custom Rain build with non-canonical selectors; production calls `takeOrders4` via SDK-generated calldata, never `takeOrders3`)
- Added `--no-rate-limit` + `--retries 5` to `anvil` so its lazy state-fetch from the parent RPC tolerates burst patterns

## Skipped tests — root cause + next step for each

### TEST-08 `no_liquidity` (`marketFailures.spec.ts:60`, currently `test.skip`)

**Architectural finding**: the UI classifier (`MarketOrder.svelte:314-329`) emits `no_liquidity` ONLY for `walkOrderbook`'s own `no_quotes`/`no_fill` outcomes. SDK-preflight liquidity errors map to `slippage` (fallback). So requesting a huge wtCOIN buy doesn't trigger `no_liquidity` — `walkOrderbook` returns partial fills (asset filled > 0), `priceError` stays false, classifier returns null.

**Working approach (passes solo)**: use **wtSPYM**. Its on-chain feed is unreachable from the fork → every wtSPYM order's `quote()` reverts during cache build → empty orderbook → walk no_quotes → classifier `no_liquidity`. Already added wtSPYM to `fixtures.ts` TOKENS.

**Suite-mode flake (3.4s fail)**: in the suite the test dies before the 90s assertion runs. Browser log fragment: `Uncaught (in promise) TypeError: Failed to fetch`. The wtSPYM page seems to close itself — possibly a legacy-symbol redirect (`legacySymbol: 'tSPYM'`) or the `priceFeedId: ''` + `fallbackPrice: 82.5` path triggers an early navigation.

**Next step**:
1. Reproduce solo first (`npx playwright test marketFailures.spec.ts -g "no liquidity"` PASSES — verified locally) to confirm the architecture
2. Open the suite-mode failure trace at `test-results/marketFailures-TEST-08-—-M-386ac-a-error-class-no-liquidity--chromium/trace.zip` — look for whether the page navigates away from wtSPYM
3. Add a page-settle wait (e.g. `await page.waitForLoadState('networkidle')` or `await page.waitForResponse(/orders\/token/)` after the goto) to absorb whatever the suite ordering causes the page to do

### TEST-08 `stale_oracle` (`marketFailures.spec.ts:113`, currently `test.skip`)

**Setup**: advances anvil time + browser `Date.now()` past Pyth's 300s freshness window before clicking submit. Expectation: SDK preflight reads on-chain Pyth, sees stale, reverts; classifier maps the SDK error string to `stale_oracle`.

**What's happening**: the error-banner with `data-error-class="stale_oracle"` never appears within 90s. The cache builds successfully (warmed by earlier marketBuy tests in suite order). The SDK preflight definitely runs — but the prep-error string it returns doesn't match the classifier's mapping (`MarketOrder.svelte:317-323` checks `prepErr.includes('oracle') || prepErr.includes('chain_unreachable')`).

**Next step**: capture the actual `prepErr` string. The diagnostic harness in `marketBuy.spec.ts:46-72` already parses `[take-order failed]` console logs — copy that into the stale_oracle test (with the appropriate error-class assertion target) and run with `-g "stale oracle"` after the suite has warmed the cache. The captured `error` field will tell you what the SDK actually says under stale-Pyth conditions; adjust the classifier mapping OR the test assertion to align.

**Cache-warmth subtlety**: the fork stub's cache is built BEFORE advanceTime is applied in the test, so cached quotes are still fresh. The UI's walk uses cached quotes and `marketPrice` populates fine. The forcing only bites at SDK-preflight time when the SDK queries anvil for fresh state. This means **the suite ordering is what makes the test viable** — if you re-run in isolation (where cache isn't pre-warmed), the cache build itself runs against the time-advanced anvil and may fail. Solution: pre-warm via a no-op goto BEFORE the advanceTime call.

### TEST-08 `market_closed` (`marketFailures.spec.ts:153`, currently `test.skip`)

**Same failure mode as stale_oracle**: error-banner never settles on `market_closed`. The classifier (`MarketOrder.svelte:325`) needs BOTH `isOutsideMarketHours() && orderPreparationError` set. ## Open architectural questions

1. **Vault balance accuracy on old forks**: the fork stub re-quotes via the Raindex SDK, but `RaindexVault.formattedBalance` comes from the subgraph cache (always LIVE), not from anvil. For forks within minutes of "now" this is fine. For genuinely old forks (4+ days) it diverges and would need a direct `eth_call` to the orderbook's `vaultBalance` function. Not currently a problem since dynamic FORK_BLOCK keeps forks recent.

2. **Goldsky free-tier ceiling**: even with the cache + retry, a long suite run can still rate-limit. CI on a paid Goldsky tier won't see this. If local-run robustness becomes important, the next step would be to capture a single full-cache snapshot to disk and have the stub seed from disk on startup.

3. **wtSPYM page early-close**: the `no_liquidity` test's flake suggests there's a real-world bug or quirk in how the trade page handles tokens with `priceFeedId: ''`. Worth investigating separately from the test — production users on wtSPYM may see similar instability.

## What NOT to do

- **Don't add stubs to bridge LIVE-vs-FORK divergence** without first checking if dynamic FORK_BLOCK + the existing two stubs handle it. The previous handover (df92215) shows what happens when stubs accumulate.
- **Don't re-implement orderbook contract calls in test code** (e.g. hand-rolled `takeOrders3` calldata). The orderbook is a custom Rain build; production uses SDK-generated calldata for `takeOrders4`. If the test needs to take an order, do it via the UI (marketBuy/marketSell) or via the SDK directly with a freshly-initialized RaindexClient.
- **Don't run E2E with Node 24** — `@sveltejs/adapter-vercel` rejects it. `nvm use 20`.
- **Don't expect public Base RPCs to work for anvil fork mode** — they reject `eth_getProof`. CI's archive secret is already configured.
