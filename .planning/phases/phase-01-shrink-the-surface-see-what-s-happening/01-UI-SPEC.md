# Phase 1 — UI Design Contract

> Visual and interaction contract for the Shrink the Surface, See What's Happening phase. Generated by gsd-ui-researcher (with user decisions on three open questions), verified by gsd-ui-checker.

## Phase UI Surface Summary

This is a **deletion-heavy phase**, not a new-surface phase. The contract therefore primarily **locks in existing design tokens** (so deletions don't accidentally drift styling) and captures three explicit decisions for the surfaces that *do* change. There are no new components, no new pages, and no new design tokens introduced in Phase 1.

**Touched surfaces:**

| Requirement | Surface | Change |
|---|---|---|
| DEPR-01 | `(main)/+layout.svelte`, `Header.svelte` | Pure code deletion of already-commented-out `RewardsDetailsModal`, `RewardsLeaderboardModal`, `RewardsDisplay` mounts; remove now-dead components from `src/lib/components/rewards/` |
| DEPR-03 | `DepositModal.svelte`, plus `OnramperModal.svelte` deletion | Remove Onramper view from `DepositModal`; modal collapses from 3-view (`options` / `buy` / `deposit`) to deposit-only flow |
| DEPR-02 (conditional) | Admin layout nav, `admin/rewards/+page.svelte`, rewards section of `admin/+page.svelte` | If "delete" decided during Phase 1 discovery, prune rewards from admin tree; if "keep with bandages," no UI change |
| OBS-05 | None | Use existing Vercel Speed Insights hosted dashboard; no new st0x UI |
| OBS-01 | None visible | SDK integration only; no `+error.svelte` shipped this phase |
| OBS-02..04 | None | Server-side instrumentation; no UI |

## Copywriting Contract

The only user-visible copy that changes in this phase is in `DepositModal.svelte`. Everything else is pure deletion (already hidden from users) or backend-only.

### DepositModal — collapsed (3-view → deposit-only)

**Decision (Q1):** Skip chooser entirely. The modal opens directly to the deposit-from-wallet view.

| Element | Copy | Rationale |
|---------|------|-----------|
| Modal title | "Deposit" | Was "Add Funds" when chooser existed; collapsing the chooser removes the umbrella concept, so the title becomes the action |
| Address label | "Your wallet address" | (existing — keep as-is) |
| Body / instructions | "Send {token} on Base to this address. Funds will appear in your st0x balance once confirmed." | Tightened from the previous chooser-flow copy that had to explain both buy and deposit; now single-purpose |
| Address copy CTA | "Copy address" | (existing — keep as-is) |
| Basescan link | "View on Basescan" | (existing — keep as-is) |
| QR caption (if present) | "Scan with your wallet" | (existing — keep as-is) |
| Close action | "Close" | (existing — keep as-is) |
| Removed copy | "Buy crypto" / "Add funds" landing screen / Onramper view title | Deleted along with the Onramper integration |

### Other surfaces

## Out of Scope for This Phase (UI-Wise)

To prevent design scope creep:

- **No design system overhaul.** Tailwind tokens, primary color, fonts, icons stay exactly as they are.
- **No new pages or routes.** All work is deletion or unchanged.
- **No `+error.svelte`.** Deferred per Q3.
- **No internal web vitals dashboard.** Vercel-hosted is sufficient per Q2.
- **No DepositModal redesign.** Only the chooser view is removed; the deposit view itself is untouched.
- **No admin-page architectural refactor.** Out of scope per `PROJECT.md` and `REQUIREMENTS.md`. Even if DEPR-02 deletes `admin/rewards/+page.svelte`, the rest of the admin tree (including the 2898-line `admin/+page.svelte` activity/tvl/swaps section) is untouched.
